# 企业微信 · 客户沟通与协作 MVP（PRD）

> 文档名：`PRD_WX_QY.md`  
> 范围：EcoTea **企业微信**产品说明（客户加好友、活码引流、内部协同）。  
> 对外获客主阵地仍为 **订阅号 + H5**（见 `PRD_WX_MP.md`）；内部查货开单见 **小程序**（`PRD_WX_MINI.md`）。  
> **本期不做服务号；全链路不做线上收款付款。**  
> 本文只描述产品能力与使用场景，不涉及表结构、接口与实现细节。

---

## 1. 目标与定位

| 维度 | 说明 |
|------|------|
| 核心定位 | **成交沟通层**：把「加个人微信」逐步转为「加企业微信客服」，沉淀客户关系 |
| 对内定位 | 员工之间的轻量协同（询价跟进、留货、回收成色沟通），不替代小程序开单 |
| 对外定位 | **不作为**内容推广主阵地；不替代订阅号发文、不替代 H5 价目浏览 |
| 收款 | **不提供**在线收付款；成交金额约定后仍走线下 / 个人转账等现有方式 |

| 触点 | 作用 | 本期 |
|------|------|------|
| 订阅号 + H5 | 推广、在售价目、回收说明、询价 | 已有，继续主阵地 |
| 企业微信 | 加客服、聊成交、客户归属与协同 | MVP |
| 小程序 | 查货、出图、开单 | 见 `PRD_WX_MINI.md` |
| 服务号 | 服务触达、授权等 | **不做** |

**主体（建议）：** 与小程序一致，优先使用 **个体工商户** 开通企业微信，便于品牌与主体统一。

**一句话分工：** 订阅号负责被看见，H5 负责被浏览，企业微信负责被聊住，小程序负责被记清。

---

## 2. 使用对象与权限

| 角色 | 谁 | 能做什么 |
|------|----|----------|
| 管理员 | 经营者 | 配置成员、活码/渠道、客户分配与继承规则；查看客户与沟通概况 |
| 客服 / 店员 | 对外沟通的员工 | 通过活码被客户添加；在企微中与客户聊天；维护客户备注与标签 |
| 内部同事 | 不对外的成员（可选） | 仅参与内部群沟通，不对外获客 |

- 客户侧仍使用个人微信，在微信中与「企业微信客服」会话。  
- 员工侧使用企业微信 App（或与微信互通能力，以企微当期产品为准）。

## 3. 功能清单

### 3.1 必须有（MVP）

| 编号 | 功能 | 说明 |
|------|------|------|
| W1 | 开通与成员入驻 | 创建企业微信；管理员、客服账号可用；对外展示名称清晰（如茶叶回收/销售客服） |
| W2 | 客户联系（加好友） | 客户可扫码 / 点链接添加企微客服；添加后可在微信中正常文字、图片沟通 |
| W3 | 联系我 / 活码（渠道码） | 至少区分：**销售咨询**、**回收咨询** 两类入口；可统计大致来源 |
| W4 | 替换对外「加微信」入口 | 「联系我们」H5、回收 H5、销售详情「立即咨询」等，逐步改为企微活码 / 企微客服，替代或并行个人微信号 |
| W5 | 客户备注与标签 | 支持备注称呼、意向（买/卖）、跟进说明；建议标签如：意向购买、意向回收、已成交、需跟进 |
| W6 | 客户归属与交接 | 员工离职或换岗时，客户可移交他人，避免客户只留在个人微信 |
| W7 | 内部沟通 | 员工间可用企微会话 / 内部群同步「某客户询价、是否留货、回收照片」等，不要求复杂 OA |

### 3.2 后续可做（非 MVP）

| 编号 | 功能 |
|------|------|
| W8 | 客户群发 / 群发助手（到货、特价提醒；控制频次，不替代订阅号） |
| W9 | 与订阅号关联（公众号菜单或文章引导「添加企微客服」） |
| W10 | 聊天侧边栏：边聊边查在售 / 打开小程序或 H5（依赖小程序与配置成熟后再做） |
| W11 | 从企微一键带出开单摘要到会话（依赖小程序单据能力） |
| W12 | 简易审批（大额回收确认等） |

### 3.3 明确不做（本期）

- 用企业微信替代订阅号做内容推广  
- 用企业微信替代小程序做查货、出图、开单  
- 企业微信内或外挂在线收款 / 支付商城  
- 服务号能力（模板消息等）挂靠本期企微范围  
- 重型 OA（考勤、排班、复杂审批流）——人少时非必须  
- 向客户群发回收价表、成本等敏感信息

## 4. 使用场景与入口结构

### 4.1 客户侧路径（MVP）

```
订阅号 / 销售 H5 / 回收 H5 / 「联系我们」
        │
        ▼
  扫企微活码（销售咨询 or 回收咨询）
        │
        ▼
  微信中添加「企业微信客服」并聊天
        │
        ├─ 询价、留货、谈价（销售）
        └─ 寄售/回收说明、成色沟通（回收）
        │
        ▼
  约定金额后线下结算（无在线支付）
        │
        ▼
  员工在小程序记销售单 / 回收单（若已上线）
```

### 4.2 员工侧日常（MVP）

| 场景 | 怎么用企微 | 和谁配合 |
|------|------------|----------|
| 客户来询某茶 | 企微里回复；需要准价/库存时自己或同事查小程序 / 现有内部价目 | 小程序或 H5 内部工具 |
| 发销售图给客户 | 小程序生成图 → 发到企微客户会话 | `PRD_WX_MINI` 出图 |
| 回收看图估价 | 客户微信发图 → 企微会话接收 → 口头/文字报价 | 不开线上收款 |
| 同事交接 | 内部群同步进度；必要时客户移交 | 管理员配置 |

### 4.3 对外入口调整原则

| 现有入口 | MVP 调整 |
|----------|----------|
| `about.html` 联系我们 | 展示企微客服活码（可暂保留个人微信作过渡） |
| 回收 H5 CTA | 优先跳转 / 展示「回收咨询」活码 |
| 销售详情「立即咨询」 | 指向「销售咨询」活码或联系我们页（已换企微） |
| 订阅号关键词「客服」 | 仍进联系页；联系页内容改为企微为主 |

## 5. 关键业务规则（产品层）

1. **对外 / 对内分离**  
   - 顾客不安装企业微信也可完成咨询（在个人微信里聊）。  
   - 员工用企业微信接待；查货开单仍走小程序（上线后）。

2. **个人微信过渡**  
   - 允许短过渡期「企微活码 + 个人微信」并行。  
   - 目标态：对外主推企微；个人号仅作备用，避免新客户再沉到私人号。

3. **渠道区分**  
   - 销售咨询与回收咨询尽量分活码，便于知道客户来意。  
   - 活码文案避免出现在线支付、商城下单等表述。

4. **敏感信息**  
   - 对客户会话中可谈约定售价 / 回收估价。  
   - 不主动群发、不在对外物料中公开完整回收价目与成本。

5. **与开单的关系**  
   - 企微负责「聊清楚」；小程序负责「记清楚」。  
   - MVP **不要求**企微与单据系统自动打通。

6. **客户资产**  
   - 新客户默认加在企微客服名下；人员变动走移交，不默认「客户跟人对走」。

## 6. 与现有微信触点的关系

| 触点 | 继续做什么 | 与企业微信的关系 |
|------|------------|------------------|
| 订阅号 | 内容、菜单、关键词查价 | 主获客；文案可引导「添加客服」到企微 |
| 销售 H5 | C 端价目、询价单 | 「立即咨询」指向企微 |
| 回收 H5 | 回收说明引流 | CTA 指向回收活码 |
| 联系我们 H5 | 客服入口页 | 内容主体改为企微活码 |
| 小程序 | 查货、出图、开单 | 作业工具；与企微会话互补，MVP 不强制打通 |
| 服务号 | — | 本期不做 |
| 企业微信 | 加好友、聊天、标签、交接 | 本 PRD |

---

## 7. 账号与开通（产品备忘）

1. 以 **个体工商户**（或与小程序相同主体）开通企业微信。  
2. 配置对外客服成员显示名称、头像，避免过于随意的个人昵称。  
3. 生成销售 / 回收活码，替换或并行挂到现有 H5。  
4. 制定简单规则：谁接待新客、如何备注标签、离职如何移交。  
5. 不在对外推文中把企业微信当成商城或支付入口。

---

## 8. 验收要点

1. 客户可通过 H5 / 联系页扫码添加企微客服，并在微信中完成文字/图片咨询。  
2. 至少存在销售、回收两类可区分的添加入口（或等价渠道区分）。  
3. 员工可对客户做备注 / 标签；人员变动时可完成客户移交。  
4. 对外主路径不再强依赖「只能加某个私人微信号」（允许过渡期并行）。  
5. 全程无在线收付款相关能力与对外商城表述。  
6. 不削弱订阅号 + H5 的获客与浏览；企微不替代小程序开单。
