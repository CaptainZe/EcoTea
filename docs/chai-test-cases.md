# chai 域关键测试用例

> 重点：**SPU / SKU**；品牌、保质期仅冒烟。  
> 配置前置见 [`chai-go-live-checklist.md`](./chai-go-live-checklist.md)。

---

## 0. 前置数据

| 准备项 | 说明 |
|--------|------|
| 上架品牌 ≥1、保质期 ≥1 | SPU 下拉依赖 |
| 字典 / 菜单 / 角色权限已配置 | 见上线清单 |
| SPU-A | 仅保存、无 SKU、下架 |
| SPU-B | 已维护多条 SKU（不同 year + prodBatch） |

编码规则（抽查用）：

| 实体 | 格式 | 示例 |
|------|------|------|
| SPU | `CHAI-%08d`（spuId） | `CHAI-00000012` |
| SKU | `CHAI-%08d-%08d`（spuId-skuId） | `CHAI-00000012-00000034` |

## 2. SPU 列表与编辑（重点）

### 2.1 列表展示与筛选

| # | 用例 | 步骤 | 期望 |
|---|------|------|------|
| S1 | 打开列表 | `/business/chai/spu/index` | 品牌名、规格、状态、图、SPU 编码展示正常 |
| S2 | 名称模糊 | 输部分关键字 | 仅命中行 |
| S3 | 品牌 | 选某一品牌 | 仅该品牌 |
| S4 | 茶类 / 年份 / 状态 | 分别筛 | 精确匹配 |
| S5 | SPU 编码精确 | 完整 `CHAI-xxxxxxxx` | 0 或 1 条；错码无结果 |
| S6 | 组合筛选 | 名称 + 品牌 + 状态 | 交集正确 |

### 2.2 新增 / 编辑

| # | 用例 | 步骤 | 期望 |
|---|------|------|------|
| S7 | 仅保存 | 添加必填项 → 保存 | 列表出现；编码自动生成；**无 SKU、强制下架** |
| S8 | 新建无默认年份 | 打开添加页 | **年份为空**（可手输或 datalist 选） |
| S9 | 编辑无 SKU | 打开 SPU-A | 状态不可上架（强制下架）；保存仍下架 |
| S10 | 编辑有 SKU | 打开 SPU-B | 状态可选上/下架；保存生效 |
| S11 | 同品牌同名提醒 | 同品牌再建同名 → 保存 | 弹出确认；**取消不存**；**确定仍可存** |
| S12 | 同品牌同名-下一步 | 同上走「下一步」 | 同样二次确认；确认后进 SKU 向导 |
| S13 | 编辑自身不误报 | 打开已有 SPU 不改名保存 | 不弹同名确认 |
| S14 | 改名撞到另一条 | 编辑改成同品牌已有名称 | 弹确认；确认后可存 |

### 2.3 行内与删除

| # | 用例 | 步骤 | 期望 |
|---|------|------|------|
| S15 | 列表「SKU」-有数据 | 点 SPU-B 的 SKU | 打开向导，**加载已有**，不重新生成 6 条 |
| S16 | 列表「SKU」-无数据 | 点 SPU-A 的 SKU | 预填 **6 个半年**（锚点=SPU 的 year+prodBatch） |
| S17 | 下一步 | 编辑页「下一步」 | 先存 SPU，再进向导 |
| S18 | 未勾选删除 | 操作 → 删除 | 提示选择记录 |
| S19 | 删无 SKU 的 SPU | 勾选 SPU-A 删除 | SPU 消失 |
| S20 | 删有 SKU 的 SPU | 勾选 SPU-B 删除 | SPU 消失；其下 SKU **一并删除** |

## 3. SKU 向导（重点）

入口：`/business/chai/sku/editBySpu/{spuId}`（或从 SPU「SKU / 下一步」）。

| # | 用例 | 步骤 | 期望 |
|---|------|------|------|
| W1 | 首次预填 | SPU-A 无 SKU 进入 | 6 行；第一行=锚点半年；向前推 |
| W2 | 再次进入 | SPU-B 有 SKU 进入 | 加载已有，不覆盖成新 6 条 |
| W3 | 价格必填 | 缺销售价/回收价/压价%/无提袋扣减提交 | 保存失败并提示 |
| W4 | 官价可空 | 不填官方价 | 可保存（若产品仍允许） |
| W5 | 半年唯一 | 两行相同 year+prodBatch | 保存失败（重复提示） |
| W6 | 增删行 | 删到 ≥1 后保存；再加一行 | 可存；列表条数正确 |
| W7 | 至少一条 | 删光全部提交 | 拒绝（至少保留一条） |
| W8 | 编码生成 | 新行保存后查库或后续再进向导 | SKU 码为 `CHAI-{spuId}-{skuId}`；编辑保留原码 |

## 4. SKU 列表（重点）

### 4.1 展示与筛选

| # | 用例 | 步骤 | 期望 |
|---|------|------|------|
| K1 | 打开列表 | `/business/chai/sku/index` | 销售价/回收价、规格、图、**SPU 编码**正常；默认偏新年份/批次 |
| K2 | 不展示 SKU 编码 | 看表头与行 | **无「SKU编码」列**（筛选也无该项） |
| K3 | 保留 SPU 编码 | 看列与筛选 | 有 SPU 编码列；可按父 SPU 编码精确筛 |
| K4 | 名称 / 品牌 / 茶类 | 分别筛 | 正确 |
| K5 | 年份 + 生产批次 | 如某年 + 上半年 | 精确匹配 |
| K6 | 状态 | 上架 / 下架 | 正确 |
| K7 | 不存在的 SPU 编码 | 乱填父编码 | 空列表 |

### 4.2 上下架 / 维护 / 删除

| # | 用例 | 步骤 | 期望 |
|---|------|------|------|
| K8 | 行内上/下架 | 点上架或下架 | 状态更新 |
| K9 | 批量上/下架 | 勾选多条 → 操作 | 批量变更 |
| K10 | 未勾选操作 | 上架/下架/删除 | 提示选择记录 |
| K11 | 「维护」 | 点某行维护 | 打开该 spuId 向导；同 SPU 全部 SKU |
| K12 | 向导改价 | 改价保存后回列表 | 价格已更新 |
| K13 | 删部分 SKU | 删 SPU-B 下一行，仍剩 ≥1 | 该行消失；父 SPU 状态不变 |
| K14 | 删光某 SPU 下 SKU | 删光该 SPU 全部 SKU | 列表无残留；若父 SPU 曾上架 → **强制下架** |
| K15 | 删光后再进向导 | K14 后从 SPU 点 SKU | 重新预填 6 条 |

> 说明：当前列表可直接上架 SKU，**不**因父 SPU 下架而自动拦截（若以后要联动需另测）。

## 5. SPU ↔ SKU 联动（高优先级）

| # | 用例 | 期望 |
|---|------|------|
| X1 | SPU 仅保存 → SKU 列表 | 该 SPU 下无任何 SKU |
| X2 | 向导保存 6 条 → SKU 列表 | 出现 6 行；父 SPU 编码一致；半年不重复 |
| X3 | SPU 删除 → SKU 列表 | 无孤儿 SKU |
| X4 | K14 后 SPU 列表 | 该 SPU 显示下架 |
| X5 | 品牌/保质期名称 | 列表显示名称，非裸 id |

## 6. 建议最短路径

1. B1、E1（冒烟）  
2. S8 → S7 → X1  
3. S16 / W1 → W3 → 填价保存 → X2、W8  
4. S1～S6、K1～K7（筛选与展示）  
5. S11、S12（同名软提醒）  
6. K8～K12、K14 → K15 → S20（级联与强制下架）

## 7. 权限抽查（可选）

| # | 用例 | 期望 |
|---|------|------|
| P1 | 无 `spu:index` / `sku:index` | 打不开对应列表 |
| P2 | 无 `sku:edit` | 向导 / 维护 / SKU 上下架失败；SPU 页「SKU」受影响 |
| P3 | 无 `spu:delete` / `sku:delete` | 删除失败或无入口 |
