# 微信小程序 · 内部工具 MVP（PRD）

> 文档名：`PRD_WX_MINI.md`（目录：`d-prd/`）  
> 范围：EcoTea **内部作业小程序**产品说明（价目、开单篮、报价单、销售/回收单、文案与存图等）。  
> 工程目录：本仓库 **`wx/wx-mini-inner/`**（对内）；对 C 端小程序若有则另目录，不混用。  
> 对外获客仍走 **订阅号 + H5**（见 `PRD_WX_MP.md`）。  
> 多租户 / 三端边界见 **`PRD_TENANT.md`**（扁平店铺租户；本小程序为店内作业主入口）。  
> UI 规范见 **[`d-ui/UI_SPEC_WX_MINI_INNER.md`](../d-ui/UI_SPEC_WX_MINI_INNER.md)**（新模块 / 新组件须先更新 UI 规范再开发）。  
> **本期不做服务号；全链路不做线上收款付款。**  
> 本文只描述产品能力与页面；报价单 / 销售单 / 回收单需**新建业务表**（DDL 另立，不在组织脚本 `SQL_TENANT.sql`）。

## 1. 目标与定位

| 维度 | 说明 |
|------|------|
| 对内定位 | 店员 / 经营者的 **作业工具**：查价目、复制销售文案、保存商品图、开单篮谈价、记报价单与销售/回收单、本店员工管理 |
| 对外定位 | **不作为** C 端卖货入口；顾客仍通过订阅号菜单进入 H5 |
| 收款 | **不提供**任何在线收款 / 付款；单据中的金额仅为约定记录，便于对账与跟进 |
| 文案 | 对 C 端文案不出现 EcoTea；小程序对内可用内部称呼；对外简介偏「库存查询 / 单据工具」 |

| 触点 | 作用 | 本期 |
|------|------|------|
| 订阅号 + H5 | 推广、在售价目、回收引流、客服 | 已有，继续主阵地 |
| 本小程序（`wx-mini-inner`） | 登录后的内部价目、文案、存图、报价与开单等 | MVP |
| 服务号 | 服务触达、授权等 | **不做** |

**主体（已定）：** 使用 **个体工商户** 注册、认证并备案后发布正式版；不采用个人主体作为正式方案。

**技术（已定）：** 原生微信小程序；UI 用原生组件即可。价目列表/详情**不要求**与对内 H5 1:1 排版，小程序侧可按触控与短路径优化。视觉与组件以 `d-ui/UI_SPEC_WX_MINI_INNER.md` 为准。

## 2. 使用对象与权限

> 组织模型见 `PRD_TENANT.md`。共享一个小程序包；登录后**必须选择工作店铺**（`tenant_id`）。  
> 登录身份为 **`employee`**，**不是** Admin 的 `sys_user`。  
> 开单 / 单据隔离在当前工作店铺；目录售价与回收参考价为**全平台统一价**。  
> 权限码为粗粒度分组，后续可再拆细；代码枚举见 `PRD_TENANT.md` §3.5。

| 角色 | 谁 | 能做什么 |
|------|----|----------|
| 店长 | 店铺经营者 | 本店销售/回收价目与单据、店铺管理（含员工，受 `employee_quota`）；库存/财务按 perm 后置；首任店长由平台开通 |
| 店员 | 员工 | 按 perm：查价目、文案/存图、开单篮、报价单、销售/回收单等 |

- 必须先登录，未登录不能使用任何业务功能。  
- 一人可授权多店；进入业务前选择当前店铺，可在「我的」中切换。  
- MVP 以账号密码登录为主；微信一键登录可后续再做。  
- **权限显隐主战场在「工作台」**：无对应分组 perm 则不展示该分组入口；首页快捷同样受 perm 约束。「首页」「我的」Tab 本身始终可进（已登录且已选店后）。  
- Admin：`admin_tenant_scope` 可多店只读；平台目标**不改**各店库存；仓库与库存写**只在本小程序**（方案 A，库存专题后）。

### 2.1 权限分组（粗粒度，可后调）

| `perm_code` | 工作台分组 | 覆盖入口（有权限才展示） |
|-------------|------------|--------------------------|
| `SALE` | 销售 | 在售价目、销售报价单、销售单 |
| `RECYCLE` | 回收 | 回收价目、回收报价单、回收单 |
| `STOCK` | 库存 | 暂缓 |
| `FINANCE` | 财务 | 暂缓 |
| `SHOP` | 店铺管理 | 员工管理（受配额） |

一组内全部入口不可见时，该分组不展示。全部入口都无时，工作台提示「暂无可用功能」。

## 3. 功能清单

### 3.1 必须有（MVP）

| 编号 | 功能 | 说明 |
|------|------|------|
| F1 | 登录 / 退出 / 选店 | 员工账号；停用不可用；多店须选工作店铺 |
| F2 | 在售价目 | 列表（品牌/品名搜索；售价、库存；无货可识别）→ 详情（规格、图、售价、库存） |
| F3 | 复制销售文案 | 与对内 H5「复制信息」同一套字段规则（见 §5.2）；**不含**对外链接、**不含**回收价 |
| F4 | 保存商品图片 | **仅当前单个商品**全部展示图存相册；不做跨商品批量存图 |
| F5 | 回收价目 | 内部列表/详情；展示回收参考价（仅登录内部可见） |
| F6 | 开单篮（类购物车） | 价目多选/加入篮；改数量、约定价；**按价目线分流**（见 §5.5） |
| F7 | 报价单 | 给客户的临时谈价记录；可改、可作废；确认后可转成对应业务单 |
| F8 | 销售单 | 已确认的销售约定；可从销售报价转入，或从在售开单篮直接开 |
| F9 | 回收单 | 已确认的回收约定；可从回收报价转入，或从回收开单篮直接开；**无收款** |
| F10 | 单据列表与详情 | 报价单 / 销售单 / 回收单分入口；按状态筛选；推进或作废 |
| F11 | 本店员工管理 | `SHOP`；受 `employee_quota`；见 `PRD_TENANT.md` |

> **实现节奏（建议）：** Tab/登录骨架（已有）→ 工作台入口墙 → 在售价目（F2～F4）→ 开单篮 + 报价/销售单表 → 回收价目与回收单据 → 员工管理。库存 / 财务暂缓。

## 4. 页面结构

```
小程序（wx/wx-mini-inner）
├── 登录
├── 选择工作店铺
└── Tab
    ├── 首页
    │   ├── 当前店铺（可进切换）
    │   └── 少量快捷入口（受 perm，如在售价目）— 不做第二个工作台
    ├── 工作台   ← 仅入口墙；列表/开单进二级页
    │   ├── 【销售】SALE
    │   │   ├── 在售价目 → 列表 → 详情（文案 F3 / 存图 F4 / 加入开单篮）
    │   │   ├── 报价单 → 列表 → 详情（可转销售单）
    │   │   └── 销售单 → 列表 → 详情
    │   ├── 【回收】RECYCLE
    │   │   ├── 回收价目 → 列表 → 详情（加入开单篮）
    │   │   ├── 报价单 → 列表 → 详情（可转回收单）
    │   │   └── 回收单 → 列表 → 详情
    │   ├── 【库存】STOCK — 暂缓
    │   ├── 【财务】FINANCE — 暂缓
    │   └── 【店铺管理】SHOP
    │       └── 员工管理
    └── 我的
        ├── 账号 / 当前店铺（切换）
        ├── 修改密码（已接：自助改密后重新登录）
        ├── 个人单量入口（单据就绪后，见 F20）
        ├── 关于 / 版本（可选）
        └── 退出登录
```

| 页面 | 作用 |
|------|------|
| 登录 / 选店 | 进入系统并写入工作租户 |
| 首页 | 店铺上下文 + 轻量快捷（勿堆满业务入口） |
| 工作台 | **只做入口墙**；无 perm 不展示 |
| 在售 / 回收价目 | 搜货、看价与库存；加入开单篮 |
| 开单篮 | 多行改数量/约定价 → 生成报价单或直接开业务单 |
| 报价单 | 谈价记录 CRUD；转销售单 / 回收单 |
| 销售单 / 回收单 | 已确认约定；状态推进与作废 |
| 员工管理 | 本店建号 / 启停 / perm（配额内） |
| 我的 | 身份、切店、退出；个人单据与设置后置 |

**三个 Tab：** 首页 | 工作台 | 我的。  
回收相关能力只出现在内部流程，不作为对外宣传页。

### 4.1 工作台原则

- **入口墙**：分组宫格或列表入口即可；不在 Tab 页堆价目列表或单据列表。  
- **重操作进二级页**：搜货、详情、开单篮、开单表单均在分包/二级页完成。  
- **库存 / 财务**：暂缓期间可不展示该分组（优于灰显占位）。

### 4.2 价目 UI（相对 H5）

- 能力对齐对内价目（搜、价、库存、文案、存图），**排版可优化**：更大触控、更短路径、原生列表/卡片即可。  
- 不必复刻 H5 DOM 结构；文案字段规则仍以 §5.2 为准。

## 5. 关键业务规则（产品层）

1. **对外 / 对内分离**  
   - 顾客：订阅号 → H5 看在售、看回收说明、加客服。  
   - 员工：小程序登录后查价目、复制销售文案、存图、报价与记单。

2. **销售文案（F3，对齐对内 H5）**  
   - 规则与对内在售价目详情「复制信息」一致（实现参考 H5 `formatKeywordPlainText`）。  
   - 结构（有值才输出该行；多行以换行连接）：  
     - 标题行：`title` 或 `name`  
     - `等级：` / `规格：` / `批次：` / `保质期：`  
     - `官方：` / `售价：`（展示串中半角括号规范为全角 `（）`，与 H5 一致）  
     - `库存数量：…`（可附小袋 / 破损等后缀，与 H5 一致）  
   - **不包含**对外详情链接、回收价、支付相关字样。

3. **保存商品图片（F4）**  
   - 范围：当前详情对应商品的展示图集合；逐张或批量写入系统相册。  
   - 需用户授权；部分失败可提示并支持重试。

4. **价格展示**  
   - 销售价：在售列表、详情、销售文案中可展示。  
   - 回收参考价：仅登录后的回收价目 / 回收开单篮 / 回收单据可见；**不得**写入销售文案或随商品图对外说明中带回收价。

5. **开单篮与单据分流（已定）**  

```
价目（多选 / 开单篮）
    ├─→ 报价单（谈价：客户、品名/成色、约定价、有效期；可改、可作废）
    │       └─→ 确认转单后锁定为「已转单」
    │               ├─ 销售报价 → 销售单
    │               └─ 回收报价 → 回收单
    └─→ 直接开业务单（跳过报价，可选捷径）
            ├─ 在售价目开单篮 → 销售单
            └─ 回收价目开单篮 → 回收单
```

| 来源 | 开单篮可生成 |
|------|----------------|
| 在售价目 | 销售报价单；可选「直接开销售单」 |
| 回收价目 | 回收报价单；可选「直接开回收单」 |

- **销售与回收开单篮分线**，避免在售明细误开成回收。  
- **报价单** = 给客户的临时报价（未成交）。  
- **销售单 / 回收单** = 已确认的业务约定（金额仅为约定记录）。  
- 转单后原报价单不得再当有效谈价单编辑（状态「已转单」）。

6. **报价单 / 销售单 / 回收单（产品字段要点）**  

| 实体 | 要点 |
|------|------|
| 报价单头 | 店、类型（销售/回收）、客户称呼或备注、有效期、状态（草稿/已报价/已转单/作废）、创建人 |
| 报价明细 | SKU 或手填品名、成色备注、数量、约定单价 |
| 销售单 / 回收单 | 可从对应报价带入；状态建议：草稿 → 已确认 → 已完成；未完成可作废 |

- 三类能力均需**新建业务表**（销售侧与回收侧建议分表或强类型字段，勿靠松散字符串混单）。  
- DDL / API 另立专题，不写入 `SQL_TENANT.sql`。

7. **库存与仓库**  
   - 价目展示库存：组织未按店拆库存前，按现网可读数据展示；拆分后为**当前工作店铺**库存。无货仍建议可查，需标明「无货」。  
   - MVP **不要求**开单后自动改库存。  
   - 目标态：本店仓库与库存写只在小程序（`STOCK`）；见 `PRD_TENANT.md`。

8. **单据金额**  
   - 仅为双方约定记录；界面与文案避免「支付」「付款」「收银台」等表述。

9. **租户隔离**  
   - 写操作必须落在当前工作店铺；不得查看或操作未授权店铺数据。

## 7. 账号与发布（产品备忘）

1. 以 **个体工商户** 为主体注册小程序并完成认证、备案后发布正式版。  
2. 简介与类目表述偏向「库存查询、内部单据、作业工具」，避免写成对外茶叶商城；**勿**再强调「价目海报/出图」。

4. 服务号本期不申请、不接入。  
5. 源码放本仓库 Git；发版另走微信开发者工具「上传 → 体验 / 审核 → 发布」（与 Git 无关）。

## 8. 验收要点

1. 未登录无法使用价目、文案、存图、开单篮与单据。  
2. 销售文案与对内 H5「复制信息」字段规则一致；无对外链接、无回收价、无支付入口。  
3. 保存商品图片仅针对当前单个商品的展示图；需授权相册。  
4. 不提供生成销售图 / 海报长图能力。  
5. 回收参考价仅出现在登录后的回收相关流程。  
6. 在售 / 回收开单篮分线；可生成对应报价单或直接开销售单 / 回收单。  
7. 报价单可改、可作废；转单后为「已转单」且不可再当有效谈价单使用。  
8. 销售单、回收单可创建、查看、推进状态或作废；金额仅为约定记录。  
9. 全程无在线收付款相关能力与文案。  
10. 对外获客路径仍以订阅号 + H5 为主，小程序不替代该路径。  
11. 多店账号须先选店再进入业务；单据均为当前店。  
12. 工作台仅入口墙，按粗粒度 perm 显隐；库存 / 财务暂缓可不展示。  
13. 有 `SHOP` 的店长可在配额内管理本店员工。
